# VidMuse 风格定义与批量聚类规则

## 1. 风格定义

不能把相同导演、作品或流派的素材直接判定为同一风格。Anchor 用于建立候选素材范围，不代表聚类结论。导演不是天然的一种风格，电影也不是天然的一种风格。它们都是待验证的 Anchor。

### 1.1 AI 实际聚类什么

以 Anchor 建立候选，以视觉规律验证候选，以生成效果决定能否入库。

```text
确定有名称的 Anchor
→ 收集该 Anchor 的素材
→ 检查是否存在稳定的视觉规律
→ 判断一个 Anchor 内需要保留一个、拆成多个，还是完全不成立
→ 与其他 Anchor 比较，处理重复
→ 用中性内容验证生成效果
```

### 1.2 第一步：Anchor 必须先存在

允许的 Anchor 是已经具有公共认知的对象：

- 导演、摄影师、艺术家、建筑师；
- 电影、动画、游戏、MV、IP；
- 工作室、艺术运动、建筑流派；
- 已形成稳定名称的亚文化审美；
- 已形成完整视觉体系的媒介技法。

`Soft Light`、`Blue Night`、`Romantic` 不是 Anchor。

`Dreamcore`、`Claymation`、`German Expressionist Cinema` 可以是 Anchor，因为它们不是临时描述，而是已有明确文化含义和作品集合的类别。

### 1.3 第二步：验证 Anchor 是否真的对应一种风格

AI 从素材中提取视觉规律。

聚类使用视觉特征（示例，不限于）：

| 维度（示例，不限于） | 判断内容 |
|---|---|
| 图像形成 | 真人摄影、2D、3D、定格、拼贴、胶片、数字影像等 |
| 色彩与明度 | 色温、饱和度、黑位、高光、整体色调组织 |
| 光线系统 | 硬光/柔光、方向、反差、实景光、轮廓光、曝光方式 |
| 构图与空间 | 景别、透视、镜头感、主体尺度、负空间、几何和空间层次 |
| 材质与后期 | 胶片颗粒、印刷纹理、色散、扫描感、渲染和表面质感 |

这些维度用于提醒 AI 观察“视觉规律如何形成”，不是摄影字段模板。绘画应重点观察笔触、线条、形体、颜料和画面空间；2D 应观察线条、形变、平面层次和动画表现；3D 应观察建模、比例、材质和渲染；平面设计应观察版式、图形、文字关系与印刷表面；建筑应观察体量、几何、材料、尺度和空间秩序。只使用当前媒介和 evidence 能支持的维度，不为了填满摄影维度而补写镜头、运镜或光线。


### 1.4 第三步：选择正确的 Anchor 层级

原则是：选择覆盖范围最大、但不会虚假概括的 Anchor。

以导演为例：

- 如果多个作品共享同一套核心视觉规律，可以使用导演名。
- 如果导演作品形成多个明显视觉簇，则导演只作为父级或检索别名。
- 如果规律只在某个时期稳定，使用“时期 + 导演”。
- 如果只在单部作品稳定，使用作品名。
- 如果单部作品内部也没有稳定规律，则不建立该风格。

父级只用于组织和检索，不默认作为用户可选风格。

因此导演规模和知名度不重要。判断标准不是“大导演还是小导演”，而是跨作品是否稳定。

例如：

```text
Denis Villeneuve
├── 如果跨作品规律稳定：Denis Villeneuve Inspired
├── 如果作品差异明显：不建立导演级可选风格
├── Dune Inspired
└── Blade Runner 2049 Inspired
```

对于流派、动漫、建筑、Dreamcore 等，也使用相同原则：

- 广义名称内部视觉一致，就保留广义名称；
- 广义名称包含多个稳定子类，就下钻到公认子类；
- 如果只能依靠临时创造的描述词拆分，则不建立独立风格。

## 2. 什么情况下是“同一种风格”

合并风格要求：

1. 只是导演、摄影师、作品名称不同，但视觉规律和生成结果基本相同。
2. 可以使用同一个 `promptSample` 主体（生成配方）。
3. 只差部分视觉特征等参数，如颜色、亮度、颗粒强度、单一镜头特征。
4. 在该风格适用范围内更换多个可比内容后，视觉身份仍然相同；内容依赖型风格只在其已声明的范围内判断。
5. Planner 面对真实项目需求时，没有明确理由只推荐其中一个。

合并后，其他名称作为搜索别名保留。

例如：

- `Denis Villeneuve Soft Light` 不应成为独立风格；
- `Wong Kar-wai` 和 `Christopher Doyle` 如果最终编译出相同配方，应合并，另一个名称作为搜索别名或来源信息；
- `Blue Night Portrait` 不能因为颜色不同就从诗性写实风格中拆出。

## 3. 什么情况下是“另一种风格”

拆分风格要求：

1. 两者都有明确、可识别的 Anchor 或 Anchor 子范围。
2. 各自拥有稳定出现的完整视觉规律，而不是单一滤镜差异。
3. 两套生成配方至少在上述五个视觉维度中的两个核心部分上必须采用不同指令。
   - 配方：用户选择风格后，VidMuse 实际写入图片和视频生成 Prompt，表现为 `promptSample`，`analysis` 是对它的详细解释。
4. 固定相同主体生成后，画面可以稳定区分。
5. 可以明确说出 Planner 在什么需求下选 A、什么需求下选 B。

## 4. 什么情况下不进入风格库

1. 没有公共认知 Anchor 的视觉效果簇；
2. 只有情绪、场景、题材或滤镜特征；
3. Anchor 很知名，但素材内部没有稳定视觉规律；
4. 风格依赖具体角色、服装、建筑或名场面；
5. 与已有风格没有实际应用差异。

## 5. Anchor 如何选择

覆盖范围最大、同时又不夸大风格一致性。

### 5.1 导演、摄影师、艺术家

满足以下条件，才使用人物作为 Anchor：

- 覆盖多个独立作品或项目；
- 核心视觉规律跨作品稳定出现，素材主要形成一个视觉簇；
- 单部作品不能主导全部证据。

如果人物的作品明显多模态，应下钻命名：

- `1990s Wong Kar-wai Cinematic`
- `Tim Burton Stop-Motion`
- 或直接使用具体作品 Anchor。

导演知名度和作品数量不是标准。个人风格鲜明的小导演和大导演使用完全相同的验证方法。

### 5.2 单部电影、动画、游戏或 IP

作品 Anchor 往往是影视类最稳妥的默认层级，但仍需满足：

- 覆盖不同场景或章节；
- 风格规律贯穿作品，而不是只存在于一个名场面；
- 去掉角色、服装、场景和世界观后仍能迁移；
- 能产生独立 Prompt 配方；
- 与导演级风格及相邻作品有明显区别。

如果一部作品内部存在多个视觉风格，作品名只能作为父级或来源，不能强行聚成一个风格。父级只用于组织和检索，不默认作为用户可选风格。

### 5.3 工作室、动画品牌

只有跨导演、跨作品、跨时期仍有稳定视觉风格时，才使用工作室名称。

例如 `Ghibli Inspired`、`Kyoto Animation Inspired` 都不能因为品牌知名就直接不加验证的成立。若工作室内部差异较大，应到导演、时期、系列或作品。

### 5.4 艺术流派、媒介技法

当规律跨多个创作者成立，并且名称已有稳定公共含义时，直接使用标准术语：

- `German Expressionist Cinema`
- `Art Nouveau`
- `Claymation`
- `Risograph Print`
- `MiniDV Diary`

这类名称不需要强行绑定名人，也不需要添加 `Inspired`。

### 5.5 建筑风格

建筑首先是内容领域。只有当它稳定控制空间几何、材料、比例、光线和构图时，才作为视觉风格。

合格方向包括 `Brutalist Architecture`、`Tadao Ando Concrete Minimalism`；单栋建筑名称或“现代建筑”通常不够。Planner 还应在项目包含建筑、室内或环境设计时才重点推荐。

### 5.6 Dreamcore、Poolcore 等社区审美

社区词可以作为 Anchor，但必须证明它对应稳定视觉配置，而不仅是若干常见物体。

允许内容依赖型风格，例如 `Poolcore` 可以要求水池或水空间；但必须明确适用范围。若去掉泳池后概念完全消失，就不能宣称它是适合任意主体的通用风格。

### 5.7 MV 风格

MV 导演只有在多个艺人、多个项目中呈现稳定视觉语言时，才能作为人物 Anchor。

单支 MV 可以使用作品 Anchor；某一艺人特定时期的多个 MV 可以使用“艺人 + 时期 + MV Aesthetic”。仅凭音乐类型，如 K-pop、Hip-hop，不能定义视觉风格。

## 6. 命名规则

命名采用：

```text
名称 = 通过验证的 Anchor + 必要的范围限定
```

- 人物：`Wes Anderson Inspired`
- 人物时期：`1990s Wong Kar-wai Cinematic`
- 作品：`Dune Inspired`
- MV：`Hiro Murai MV Aesthetic`
- 流派：`German Expressionist Cinema`
- 社区审美：`Dreamcore`
- 技法：`MiniDV Diary`
- 建筑：`Brutalist Architecture`

只允许加入一个真正用于区分边界的限定词。禁止把多个普通特征拼成冗长名称，也禁止为了满足 Anchor Principle 随意关联一个名人。

## 7. 最终可执行规则

- 风格必须有预先存在、可以解释的 Anchor，不接受无 Anchor 视觉簇直接入库。
- 视觉聚类只负责验证、拆分和去重，不负责凭空创造风格类别。
- 风格库优先保证少而明确、可匹配、可执行，接受牺牲一部分覆盖量，不以视觉滤镜数量作为丰富度。

批量聚类原则：

1. 风格必须先有明确 Anchor。Anchor 可以是人物、作品、工作室、流派、技法或已有名称的社区审美；临时视觉描述不能作为 Anchor。
2. AI 以 Anchor 为单位收集素材并验证，不以全量视觉聚类直接生产风格。
3. 风格必须具有稳定视觉规律。视觉规律由当前媒介适用的多个维度共同形成，例如图像形成或笔触造型、色彩与明度、光线或体积、构图或版式与空间、材质与完成方式；不能只有单一颜色、滤镜或情绪。
4. 人物或工作室 Anchor 须跨项目成立。不成立时下钻到时期、系列或单部作品。
5. 作品 Anchor 须跨场景成立。去掉角色、地点、服装和名场面后，规律仍应可迁移。
6. 同一 Anchor 内可以拆分，但子风格也必须有可解释的时期、作品或公认子类名称。不为无名滤镜差异制造新风格。
7. 不同 Anchor 不自动成为不同风格。如果视觉规律、生成配方和 Planner 使用场景相同，应合并并保留搜索别名。
8. 两种风格只有在 Anchor、视觉规律、生成结果和 Planner 选择上都存在实际差异时才并列入库。
9. 生成验证使用双方适用范围内的相同可比内容。内容依赖型或范围受限的风格，应在其范围内更换多个内容验证迁移性。只有需要替换至少两个核心视觉控制，并能产生稳定可见差异，才认为生成配方不同。
10. 无法通过以上判断的候选不入库。允许保留为素材标签或研究候选，但不能为了扩充数量进入官方风格库。
11. 聚类候选进入人工确认前，应查询所选环境的实时官方风格库，完成查重、近邻和增量价值判断；同时汇报本批候选的视觉形态与 Anchor 构成，并给出非约束性的推进比例建议。建议只帮助人工平衡质量与覆盖，不自动淘汰候选，也不得反向限制前序素材采集。
